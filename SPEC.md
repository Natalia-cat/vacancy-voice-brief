# SPEC — Голосовой бриф вакансии

> Версия 0.3 · 10.11.2026 · пайплайн в прототипе — имитация (D6) · добавлены разделы «Вакансии» и «Профиль»
> Источник: Figma spec (живая версия). Эта копия — для агентной разработки.
> Документ — основной артефакт фичи. Прототип собирается агентом строго по нему.
> Если реализация расходится со спецификацией — правится спецификация или код, но не «додумывается».
> Пометка **[РЕШЕНИЕ]** — выбор автора там, где ТЗ допускает разные трактовки.

## 1. Задача

**Пользователь:** бизнес-заказчик (руководитель, у которого открывается вакансия). Не HR, не пишет вакансии регулярно, времени мало, формы не любит.

**Job story:** когда мне нужен новый сотрудник, я хочу за пару минут рассказать своими словами, чем он будет заниматься, — чтобы получить готовое описание вакансии и не разбираться в HR-формах.

**Результат фичи:** структурированное описание вакансии, собранное из 4 голосовых ответов, которое заказчик может поправить и скопировать.

**Принцип:** пользователь разговаривает, система делает остальное. Вся обработка (распознавание, проверка полноты, генерация) скрыта; наружу видны только прогресс и, при необходимости, одно короткое уточнение.

## 3. Скоуп

### В скоупе

- 4 вопроса, голосовой ответ, live-транскрипт.
- Кольцо прогресса (4 сектора, 72 деления) с тремя уровнями заполнения.
- Проверка полноты ответа по слотам (имитация правилами, D6), одно уточнение на вопрос.
- Генерация вакансии, редактирование, копирование.
- Текстовый ввод как полноценная альтернатива голосу.
- Возврат к предыдущему вопросу, восстановление после перезагрузки.
- Демо-режим с заготовленными ответами.

### Вырезано

| **Что** | **Почему** |
|---|---|
| Серверное распознавание (Whisper и т.п.) | 24 часа на задание. Web Speech API покрывает Chrome/Edge; для остальных есть текстовый ввод. |
| Реакция кольца на громкость голоса | Дорого по времени, информации не добавляет. Заменено пульсацией «слушаю». |
| Авторизация, публикация на площадки | Не нужны для проверки гипотезы «голос → вакансия». Список вакансий и профиль — на клиенте, без аккаунта. |
| Мультиязычность | Аудитория и вопросы — русскоязычные. |
| Сводный экран «проверьте ответы» перед генерацией | Лишний шаг. Правка возможна в результате и через возврат к вопросу. |
| Хранение аудио | Не нужно продукту, создаёт риски приватности. |
| Реальная LLM в прототипе | Проверяется UX, а не модель. Контракт готов к замене (раздел 13). |
| Сервер | Без LLM он не нужен: прототип — статический сайт. |

## 4. Основной сценарий

1. **Интро.** Одна фраза о том, что будет, кнопка «Начать». Подпись: «4 вопроса · около 3 минут · можно текстом».
2. **Доступ к микрофону.** Браузерный запрос. Отказ → текстовый режим (не ошибка).
3. **Вопрос 1–4.** Пользователь нажимает на кольцо (или пробел) → говорит → видит live-транскрипт и как растёт сектор → останавливает запись (или пауза 3 с).
4. **Проверка** (обычно около 1 с). Сектор дозаполняется. Если ответ неполный — одно уточнение, запись продолжается в тот же ответ.
5. После 4-го вопроса кольцо замыкается → морфинг в галочку → **генерация**.
6. **Результат:** карточка вакансии. Иконки «Редактировать» и «Скопировать», «Сохранить» (в список вакансий), «Начать заново».

## 5. Вопросы и слоты

Слот — смысловой элемент, который должен присутствовать в ответе. Полнота = доля заполненных обязательных слотов.

| **ID** | **Текст в интерфейсе** | **Подсказка** | **Обязательные слоты** | **Правило полноты** | **Уточнение** |
|---|---|---|---|---|---|
| q1 | Какие 2–3 задачи новый сотрудник будет решать каждый день? | Например: «разбирать заявки клиентов, готовить отчёты» | `tasks[]` (≥ 2 разных задачи) | 2+ задачи → 1.0; 1 задача → 0.5; 0 → 0 | «Назовите ещё одну задачу, которую он будет делать регулярно» |
| q2 | Над каким проектом он будет работать первые полгода? | Что это за проект и какой результат от него нужен | `project`, `goal` | заполненные / 2 | «А какой результат по этому проекту нужен через полгода?» |
| q3 | Через полгода он продолжит этот проект или возьмётся за другой? | Если за другой — за какой | `decision` (continue / switch / unknown), `next_project` (только при switch) | continue или unknown → 1.0; switch без проекта → 0.5 | «За какой проект он возьмётся дальше?» |
| q4 | Какие инструменты, программы и знания ему нужны? | Программы, сервисы, области знаний | `tools[]` (≥ 1), `knowledge[]` (≥ 1) | заполненные / 2 | «А какие знания или опыт ему понадобятся, кроме инструментов?» |

`decision = unknown` («пока не знаем») — честный и полный ответ, уточнение не задаётся.

## 6. Модель прогресса (кольцо)

- 72 деления, 4 сектора по 18. Между секторами — зазор в одно деление.
- Активный сектор подсвечен: его пустые деления ярче, чем у будущих секторов.

### Состояния деления

| **Состояние** | **Вид** | **Когда** |
|---|---|---|
| `off` | `color/text-a7` | Нет данных |
| `off-active` | `color/text-a22` | Пустое деление активного сектора |
| `live` | `color/accent-a40` | Растёт во время речи (уровень **min**) |
| `filled` | `color/accent` | Подтверждено проверкой (уровень **medium**) |
| `gap` | контур `color/accent`, без заливки | Ответ принят без уточнённого слота |

### Расчёт

- **Во время речи (min):** `live = min(6, floor(words / 5))` — ответ из 30+ слов даёт 6 делений. Сигнал «я вас слышу», а не оценка.
- **После проверки (medium):** `filled = round(18 × score)`, где `score` — полнота из таблицы раздела 5.
- Деления сверх `filled`, которые были `live`, гаснут до `off-active` за 300 мс (без резкого «слива»).
- Если ответ принят после уточнения неполным: недостающие до 18 деления → `gap`.
- Если проверка недоступна (ошибка/таймаут): сектор заполняется `filled` по уровню min, недостающие → `gap`. Пользователь не видит ошибку.
- Кольцо **никогда не уменьшается** без действия пользователя. Единственное исключение — перезапись ответа (сектор сбрасывается и заполняется заново).

## 7. Состояния (state machine)

| **Состояние** | **Что видит пользователь** | **Переходы** |
|---|---|---|
| `intro` | Заголовок, одна фраза, «Начать», ссылка «Посмотреть демо» | Начать → `mic_request`; Демо → `demo`; есть сохранённый прогресс → `resume_prompt` |
| `resume_prompt` | «Продолжить с вопроса N?» · «Продолжить» / «Начать заново» | → `question_ready` (вопрос N) / `intro` с очисткой |
| `mic_request` | Вопрос 1 и подпись «Разрешите доступ к микрофону» | Разрешено → `question_ready`; отказ или нет API → `text_mode` |
| `question_ready` | Вопрос, подсказка, кольцо с кнопкой записи, «Ответить текстом», «Назад» (с q2) | Клик/пробел → `listening`; текст → `text_input` |
| `listening` | Пульсация центра, live-транскрипт, рост `live`-делений, «Готово» | Готово / тишина 3 с при ≥ 3 словах → `checking`; нет речи 8 с → подсказка; 120 с → автостоп → `checking`; вкладка скрыта → `paused` |
| `paused` | «Запись на паузе» · «Продолжить» | → `listening` |
| `text_input` | Поле ввода, «Готово» (активна при ≥ 3 словах) | → `checking` |
| `text_mode` | Как `question_ready`, но вместо записи поле ввода. Плашка: «Микрофон недоступен — отвечайте текстом» | Готово → `checking` |
| `checking` | Транскрипт остаётся, кольцо замерло | полный → `accepted`; неполный, уточнений 0 → `clarify`; неполный, уточнений 1 → `accepted` с `gap`; ошибка → `accepted` (деградация) |
| `clarify` | Транскрипт + карточка уточнения, кольцо ждёт | Голос/текст → дописывается к тому же ответу; «Пропустить» → `accepted` с `gap` |
| `accepted` | Сектор дозаполняется, через 600 мс переход | → следующий `question_ready` или `generating` после q4 |
| `generating` | Кольцо замыкается → галочка. Фазы: «Собираю задачи» → «Описываю проект» → «Формулирую требования» | Успех → `result`; ошибка → `generation_error` |
| `generation_error` | «Не получилось собрать вакансию. Ответы сохранены.» · «Попробовать снова» | → `generating` |
| `result` | Карточка вакансии, иконки «Редактировать» и «Скопировать», «Сохранить», «Начать заново» | Начать заново → подтверждение → `intro` с очисткой |
| `demo` | Тот же путь, ответы печатаются автоматически, плашка «Демо» | Проходит все состояния до `result`. Выход — «Попробовать самому» |

**Назад:** в `question_ready` на q2–q4. Открывает предыдущий вопрос с его транскриптом и кнопкой «Перезаписать». Перезапись сбрасывает сектор.

## 8. Ошибки

| **Код** | **Причина** | **Текст** | **Восстановление** |
|---|---|---|---|
| `E_MIC_DENIED` | Отказ в доступе | «Микрофон недоступен — отвечайте текстом» | Текстовый режим, ссылка «Как включить микрофон» |
| `E_STT_UNSUPPORTED` | Нет Web Speech API (Firefox, часть Safari) | Как выше | Текстовый режим |
| `E_NO_SPEECH` | Тишина 8 с | «Не слышу вас — говорите ближе к микрофону или ответьте текстом» | Запись продолжается |
| `E_TOO_SHORT` | Меньше 3 слов | «Расскажите чуть подробнее» | Остаёмся в вопросе, сектор не заполняется |
| `E_STT_NETWORK` | Сетевая ошибка распознавания | «Связь прервалась. Сказанное сохранено» | Транскрипт сохраняется, «Продолжить» |
| `E_CHECK_FAILED` | Ошибка проверки | Не показывается | Деградация (раздел 6) |
| `E_GENERATE_FAILED` | Ошибка генерации | «Не получилось собрать вакансию. Ответы сохранены.» | «Попробовать снова» |

Технические тексты, коды и стектрейсы пользователю не показываются никогда.

## 9. Прерывания

- **Перезагрузка / закрытие вкладки:** ответы, номер вопроса и счётчики уточнений сохраняются в `localStorage` (`vacancy-brief:v1`) после каждого `accepted`. При возврате → `resume_prompt`.
- **Переключение вкладки во время записи:** запись на паузу, сказанное сохраняется.
- **Остановка на середине:** «Готово» допустимо в любой момент при ≥ 3 словах.
- **Уход во время генерации:** при возврате генерация запускается заново.
- **«Начать заново»:** подтверждение «Ответы удалятся» → очистка хранилища.

## 10. Интерфейс

Бриф — раздел «Главная»: центр композиции — кольцо, вопросы меняются внутри одного экрана. Навигация между разделами — шапка (web) или нижняя панель (Android). Макеты: файл «Голосовой бриф вакансии — тестовое», страницы «Макеты web» и «Макеты Android».

### Элементы и зачем они нужны

| **Элемент** | **Задача пользователя** | **Без него** |
|---|---|---|
| Кольцо | Видеть, сколько осталось и насколько хорошо отвечаю | Непонятна длина пути, нет обратной связи о качестве |
| Кнопка записи в центре кольца | Одна точка действия, куда и так смотрю | Взгляд мечется между кольцом и кнопкой |
| Live-транскрипт | Убедиться, что меня правильно поняли | Недоверие к распознаванию |
| Подсказка под вопросом | Понять, какой ответ ожидается | Ответы «в сторону», больше уточнений |
| Уточнение | Дополнить ответ, не начиная заново | Либо слабая вакансия, либо блокировка |
| «Пропустить» у уточнения | Не застрять, если ответа нет | Ощущение экзамена, брошенный сценарий |
| «Ответить текстом» | Ответить, когда говорить нельзя | Потеря пользователей без микрофона или в опенспейсе |
| «Назад» | Исправить ответ | Ошибка в ответе = рестарт |
| «Вопрос 2 из 4» | Точный номер для тех, кто не считывает кольцо | Кольцо недоступно для скринридера |
| Редактирование результата | Поправить формулировку, вписать должность | Копирование в другой редактор ради одной правки |
| Иконка «Редактировать» у заголовка | Явно перейти к правке текста | Неочевидно, что карточку можно менять |
| «Сохранить» | Сохранить вакансию в список «Вакансии» | Результат пропадает после закрытия |
| Иконка «Скопировать» рядом с заголовком | Унести вакансию туда, где её публикуют | Ручное выделение текста |
| Навигация (шапка web / нижняя панель Android) | Перейти к списку вакансий или профилю | Созданные вакансии некуда сохранять и негде найти |

### Карточка результата

Блоки: **Должность** (пустое поле, заполняет пользователь) · **Коротко о роли** · **Задачи** · **Проект на первые полгода** · **Что дальше** · **Инструменты и знания** · **Стоит уточнить** (только если есть `gap`).

У заголовка две иконки: «Редактировать» (блоки карточки становятся редактируемыми) и «Скопировать» (весь текст в Markdown, затем уведомление «Скопировано»). Подписи для скринридера — «Редактировать вакансию» и «Скопировать вакансию». Главное действие внизу — «Сохранить»: вакансия попадает в раздел «Вакансии». «Начать заново» — Outlined-кнопка рядом.

### Навигация и разделы

- Разделы: **Главная** (голосовой бриф), **Вакансии** (список созданных), **Профиль** (настройки брифа и аккаунт).
- Web — шапка с разделами; Android — нижняя навигационная панель (3 раздела).
- **Вакансии:** список со статусами «Готова», «Уточнить · N», «Черновик». Черновик продолжает бриф с вопроса, на котором остановились; готовая вакансия открывает карточку. Новая вакансия создаётся из раздела «Главная» — отдельной кнопки на экране списка нет.
- **Профиль:** имя, роль, компания, количество созданных вакансий, текущий тариф и срок его действия, настройки брифа (язык распознавания, ответ по умолчанию, подсказки к вопросам), уведомления, выход.

## 11. Движение

| **Что** | **Длительность** | **Easing** |
|---|---|---|
| Деление `off → live` | 120 мс | ease-out |
| Деление `live → filled` | 240 мс, волной с задержкой 12 мс на деление | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| `live → off-active` (не подтвердилось) | 300 мс | ease-in |
| Смена вопроса | 400 мс: старый уходит вверх с затуханием, новый появляется снизу | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| Пульсация «слушаю» | 1.6 с цикл, scale 1 → 1.06 | ease-in-out |
| Замыкание кольца → галочка | 700 мс | spring (stiffness 200, damping 22) |

`prefers-reduced-motion: reduce` — все переходы заменяются на fade 150 мс, пульсация отключается, волна делений — мгновенная.

Источник истины — страница **Design system** в файле макетов (переменные коллекции Tokens и текстовые стили). Тёмная тема, светлая — вне скоупа.

## 13. Пайплайн: имитация и контракт

Пайплайн — две функции с асинхронным интерфейсом. В прототипе они работают на клиенте по правилам ниже. Для продакшна заменяются на запросы к LLM **без изменений интерфейса**.

```ts
check(questionId, transcript): Promise<CheckResult>
generate(answers): Promise<Vacancy>

type CheckResult = {
  score: number                  // 0..1, полнота по таблице раздела 5
  slots: Record<string, string | string[]>
  missing: string[]              // незаполненные обязательные слоты
  clarification: string | null   // null, если score = 1
}

type Vacancy = {
  title: string                  // в имитации пустая строка → поле «Название должности»
  summary: string
  tasks: string[]; project: string; outlook: string
  tools: string[]; knowledge: string[]
  toClarify: string[]            // из gap-слотов
}
```

### Имитация check — правила по вопросам

Текст приводится к нижнему регистру, лишние пробелы убираются.

| **Вопрос** | **Слот** | **Правило** |
|---|---|---|
| q1 | `tasks[]` | Разбить по запятой, точке с запятой, точке, союзам «и», «а также», «затем», «ещё»; оставить фрагменты из ≥ 2 слов. Число фрагментов = число задач |
| q2 | `project` | Ответ ≥ 4 слов → заполнен (весь ответ до маркера цели) |
| q2 | `goal` | Есть маркер: «чтобы», «цель», «результат», «запуст», «довести», «сделать», «внедр», «увелич», «сократ», «к концу», «до конца» |
| q3 | `decision` | unknown: «не знаю», «пока не», «посмотрим», «неизвестно», «не решили». switch: «друг», «перейд», «возьм», «нов». continue: «продолж», «останет», «тот же», «этот же», «дальше будет». Проверка в этом порядке; ни одного маркера → слот пуст |
| q3 | `next_project` | При switch: после маркера есть ≥ 2 слов |
| q4 | `tools[]` | Слова латиницей, «1с», или маркеры «программ», «сервис», «инструмент», «excel», «таблиц», «crm» |
| q4 | `knowledge[]` | Маркеры «знат», «знани», «понима», «опыт», «умет», «разбира», «навык» |

Задержка ответа: случайная 700–1200 мс. Без неё уточнение появляется мгновенно и выглядит как ошибка ввода.

### Имитация generate — шаблон

- `summary`: «Сотрудник будет {задачи через запятую}. Первые полгода — {проект}.»
- `outlook`: continue → «Продолжит развивать этот проект»; switch → «Перейдёт на {next_project}»; unknown → «Планы на вторые полгода пока не определены».
- Списки — из слотов, с заглавной буквы, без дублей.
- `title` — пустой. Карточка показывает поле «Название должности» в режиме правки. Угадывать должность правилами нельзя, а выдуманная должность хуже пустого поля (раздел 15).
- Задержка: 2600 мс, фазы раздела 7 успевают смениться.

### Показ ошибок в прототипе

URL-параметр `?fail=check` или `?fail=generate` заставляет функцию вернуть ошибку. Нужен, чтобы проверяющий увидел состояния ошибок, которые иначе не воспроизвести.

### Замена на LLM (продакшн)

- Функции идут на сервер (`POST /api/check`, `POST /api/generate`), ключ — только на сервере.
- Модель возвращает JSON строго по типам выше; невалидный JSON = ошибка.
- Таймауты клиента: проверка 8 с (дальше — деградация, раздел 6), генерация 25 с.
- **Правило генерации:** не выдумывать факты, которых нет в ответах. Недостающее — в `toClarify`.

## 14. Доступность

- Всё управление доступно с клавиатуры: пробел — запись/стоп, Enter — «Готово», Esc — отмена записи.
- Кольцо — `role="progressbar"` с `aria-valuenow` (0–100) и текстом «Вопрос N из 4, заполнено X%».
- Уточнения и ошибки объявляются через `aria-live="polite"`.
- Контраст текста не ниже 4.5:1; состояние деления передаётся не только цветом (`gap` — контур).

## 15. Чего делать нельзя

- Блокировать переход дальше из-за неполного ответа. Максимум одно уточнение.
- Терять сказанное при любой ошибке, паузе, перезагрузке.
- Показывать технические ошибки, коды, «Error 500», JSON.
- Уменьшать кольцо без действия пользователя.
- Выдумывать в вакансии то, чего не было в ответах, в том числе название должности.
- Хранить или отправлять аудио.
- Добавлять элементы, которых нет в разделе 10, без обоснования через задачу пользователя.

## 16. Критерии приёмки

**AC-1. Голосовой ответ.** Дано: Chrome, микрофон разрешён, вопрос q1. Когда пользователь говорит, то транскрипт появляется в течение 1 с, а `live`-деления растут по формуле раздела 6.

**AC-2. Автостоп.** Дано: идёт запись, сказано ≥ 3 слов. Когда тишина длится 3 с, то запись останавливается и начинается проверка.

**AC-3. Полный ответ.** Дано: ответ на q1 содержит 2 задачи. Когда проверка завершилась, то сектор заполнен 18 делениями `filled`, уточнения нет, через 600 мс открыт q2.

**AC-4. Неполный ответ.** Дано: ответ на q1 содержит 1 задачу. Когда проверка завершилась, то заполнено 9 делений, показано уточнение, запись дописывает тот же ответ.

**AC-5. Второе уточнение не задаётся.** Дано: после уточнения ответ всё ещё неполный. Когда проверка завершилась, то ответ принят, недостающие деления в состоянии `gap`, открыт следующий вопрос.

**AC-6. Пропуск уточнения.** Когда пользователь нажимает «Пропустить», то ответ принят с `gap`, пробел попадает в блок «Стоит уточнить».

**AC-7. Отказ в микрофоне.** Когда пользователь отказал в доступе, то интерфейс переходит в текстовый режим без экрана ошибки, путь проходится до результата.

**AC-8. Браузер без Web Speech API.** Дано: Firefox. Когда открыта страница, то сразу доступен текстовый режим, путь проходится до результата.

**AC-9. Сбой проверки.** Дано: открыт `?fail=check`. Тогда ответ принят по уровню min, пользователь не видит ошибку.

**AC-10. Сбой генерации.** Дано: открыт `?fail=generate`. Тогда показан экран `generation_error`, «Попробовать снова» повторяет запрос с теми же ответами.

**AC-11. Перезагрузка.** Дано: приняты ответы на q1–q2. Когда страница перезагружена, то показан `resume_prompt`, «Продолжить» открывает q3 с заполненными секторами 1–2.

**AC-12. Назад и перезапись.** Дано: открыт q3. Когда пользователь нажимает «Назад», то открыт q2 с транскриптом; «Перезаписать» сбрасывает сектор 2.

**AC-13. Результат.** Дано: все 4 ответа приняты. Когда генерация завершена, то карточка содержит все блоки раздела 10; блок «Стоит уточнить» есть только при `gap`.

**AC-14. Без выдумок.** Дано: в ответах не упомянуты зарплата и формат работы. Тогда в карточке их нет, а поле должности пустое.

**AC-15. Копирование.** Когда пользователь нажимает иконку копирования, то в буфере Markdown-текст вакансии с учётом правок и показано уведомление «Скопировано» (1.5 с).

**AC-16. Демо.** Когда пользователь нажимает «Посмотреть демо», то весь путь проходится автоматически без микрофона за ≤ 40 с.

**AC-17. Reduced motion.** Дано: включено `prefers-reduced-motion`. Тогда анимации раздела 11 заменены на fade, пульсации нет.

**AC-18. Клавиатура.** Весь путь проходится без мыши.

## 17. Метрики

| **Метрика** | **Что показывает** |
|---|---|
| Доля дошедших от «Начать» до результата | Работает ли формат в целом |
| Брошенные сценарии по вопросам | Какой вопрос непонятен или неудобен |
| Уточнений на ответ, по вопросам | Насколько вопросы и подсказки ведут к полному ответу |
| Доля `gap` в результатах | Качество итоговых вакансий |
| Доля текстового ввода | Насколько голос реально нужен пользователям |
| Время от «Начать» до результата | Обещание «около 3 минут» |
| Доля и объём правок в карточке | Доверие к генерации |

## 18. Технические рамки

- Vite + React + TypeScript, Framer Motion. Статический сайт без сервера, публикация на GitHub Pages через GitHub Actions при каждом push в main.
- Пайплайн — модуль `src/pipeline/` с функциями `check` и `generate` (раздел 13).
- Распознавание: Web Speech API, `lang = "ru-RU"`, `continuous = true`, `interimResults = true`.
- Состояния — явная state machine (reducer), без разрозненных флагов.
- Кольцо — один SVG, деления генерируются из данных, без растровых ассетов.
- Токены — из страницы Design system, без захардкоженных цветов.
