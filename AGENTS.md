# AGENTS.md — правила для агентной разработки

Этот файл читает ИИ-агент (Claude Code, Codex, Cursor) перед любой задачей в репозитории.

## Источник истины

1. **`SPEC.md`** — что и как должно работать: сценарий, состояния (§7), ошибки (§8), прерывания (§9), запреты (§15), критерии приёмки (§16). Если задача противоречит спецификации — остановись и спроси, не «додумывай».
2. **Figma, страница Design system** — токены, типографика, компоненты. В коде они живут в `src/styles/tokens.css` с теми же именами (`color/accent` → `--color-accent`).
3. **Figma, страницы «Макеты web» / «Макеты Android»** — компоновка экранов.

Меняешь поведение → сначала правка `SPEC.md`, потом код. Код без строки в спецификации — не принимается.

## Стек и команды

- Vite + React 18 + TypeScript (strict), Framer Motion. Без сервера.
- `npm run dev` — локально, `npm test` — тесты пайплайна (vitest), `npm run build` — сборка.
- Публикация: push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → GitHub Pages.

## Структура

```
src/
  pipeline/      check + generate — контракт SPEC §13 (имитация правилами), тесты рядом
  brief/         machine.ts — state machine брифа (reducer), useSpeech.ts — Web Speech API,
                 storage.ts — localStorage, demo.ts — сценарий демо
  components/    Ring (кольцо, SPEC §6), Icons
  screens/       Brief, Result, Vacancies, Profile
  styles/        tokens.css (из Figma), global.css
```

## Правила

- **Состояния только через `reducer` в `brief/machine.ts`.** Никаких разрозненных `useState`-флагов для фаз брифа.
- **Никаких хардкод-цветов, размеров шрифта и отступов** — только CSS-переменные из `tokens.css`. Нужен новый токен → сначала в Figma Design system.
- **Пайплайн не меняет интерфейс.** `check()` и `generate()` асинхронные и возвращают типы из `pipeline/types.ts`. Замена на LLM = замена тела функций, не экранов.
- **Не выдумывать данные в вакансии** (SPEC §15): нет в ответах → в `toClarify`. Название должности не генерируется.
- **Ошибки пользователю — только тексты из SPEC §8.** Никаких `Error`, кодов, JSON в интерфейсе.
- **Не терять сказанное.** Любая ошибка, пауза, перезагрузка сохраняет транскрипт.
- **Доступность:** каждая кнопка-иконка с `aria-label`; уточнения и ошибки — в `aria-live`; всё доступно с клавиатуры (SPEC §14); `prefers-reduced-motion` уважается.
- **Тексты интерфейса — на русском**, обращение на «вы», без восклицаний.

## Definition of done

- [ ] Поведение совпадает с SPEC; затронутые критерии приёмки (§16) проверены руками в Chrome и Safari/Firefox (текстовый режим).
- [ ] `npm test` и `npm run build` проходят без ошибок и предупреждений TypeScript.
- [ ] Проверены состояния: загрузка, пустота, ошибка (`?fail=check`, `?fail=generate`), долгая операция, прерывание (перезагрузка, смена вкладки).
- [ ] Мобильная ширина 360 px: ничего не обрезано, главные действия видны.
- [ ] Если поведение изменилось — `SPEC.md` обновлён в том же коммите.

## Чего не делать

- Не добавлять сервер, авторизацию, аналитику, новые зависимости без согласования.
- Не хранить и не отправлять аудио.
- Не трогать формулы кольца (SPEC §6) и пороги проверки (SPEC §13) без правки спецификации и тестов.
